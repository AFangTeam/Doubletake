# Doubletake

两台相机拍同一个东西，并排比给别人看 —— 然后一键导出，直接进视频。

[English](README.md) · 简体中文

> 本项目以英文为准维护，这份是同步翻译。

你带了两个机身、或者两支镜头出门，同一个东西各拍了一遍。回来要把差别**讲给别人看**：得先找出真正对应的那两张、对齐、放大到同一个角落、再导成剪辑能用的图。

Doubletake 就是为这一套流程做的。

## 怎么用

**1 · 指向两个文件夹。** A 轨放一台相机的片，B 轨放另一台的。每张照片按 **EXIF 拍摄时间**落在共享的时间轴上 —— 两次拍摄是按时间先后对上的，不是按文件名排的。

**2 · 修掉时钟漂移。** 两台相机的时间永远对不齐：一台快三十秒，另一台的时区还是出厂设置。每条轨有自己的时间偏移，用 jog wheel 拖着调 —— 拖动微调，<kbd>Shift</kbd> 精细（慢 10 倍），<kbd>Option</kbd> 粗调（快 10 倍），每跨过一整秒有一次轻触觉反馈。对齐一次，文档就记住了。

**3 · 找到成对的那张。** 从任意一张，跳到另一条轨里拍摄时间最接近的那张 —— 通常就是你要的那张。

**4 · 对比。** 两张并排。放大之后**两边一起平移**；构图没对严的时候，按住 <kbd>⌘</kbd> 拖动就只动起手那一侧。EXIF 浮层只标出两张之间**真正不一样**的参数，不用自己肉眼扫两坨元数据。

**5 · 导出给剪辑用。** 一条命令写出一个命名文件夹，里面是：

| 文件 | 是什么 |
|---|---|
| `comparison.jpg` | 你当下看到的画面，带 zoom 和位移 |
| `original_comparison.jpg` | 两张未经调整、平摆左右 |
| 两张原图 | 原样保留 |
| `comparison-info.json` | 视图参数和 EXIF 摘要，之后想复刻这一帧可以读它 |

导出规格是奔着 **4K 视频插图**去的：约 8K 长边、JPEG quality 0.92。（同分辨率下 PNG 在照片内容上会涨到 100MB 左右，而肉眼看不出差别。）

## 还有

- **时间轴空白段可折叠** —— 两场之间隔了三小时，不会把整个视图吃掉
- **保存对比** —— 给一组 A/B 命名存下来，之后一键跳回
- **红心收藏** —— 挑出留用的，整组导出
- **在 app 里把原片移到废纸篓** —— RAW+JPG 成对时当作一张，两个文件一起走

## 支持的格式

JPG/JPEG · HEIC/HEIF · PNG · TIFF · RAW（ARW、CR2、CR3、NEF、NRW、RAF、RW2、DNG、ORF、PEF、SRW、RWL、SRF）

同名的 RAW 和 JPG 算**一张照片**，不是两张。

## 当前状态

**只支持照片。** 扫描时遇到的视频文件会被跳过并计数 —— 视频支持是有意暂不做的。

这是作者自己在用的工具，不是已发布的产品：没有签名版本、没有 Release，需要自己从源码编译 —— 要分发能直接跑的二进制，需要付费的 Apple 开发者账号做签名和公证，目前还没有。

源码目录和 bundle identifier 仍然写着 `Timeline`，那是项目最早的名字。这是有意保留的：文档类型 `com.ericfang.timeline.compare` 已经写进了每一个存过的 `.timelinecompare` 文件里，改掉会让它们全部认不出来。

## 编译

需要 **macOS 26** 和带 macOS 26 SDK 的 Xcode。

```bash
git clone https://github.com/AFangTeam/Doubletake.git
cd Doubletake
open Timeline.xcodeproj
```

然后 ⌘R。需要在 target 的 Signing & Capabilities 里填你自己的签名团队。

## 文档格式

一个 `.timelinecompare` 文档是个包，装着 `compare.json`（轨道配置、时间偏移、收藏、保存的对比）和指向那两个文件夹的 security-scoped bookmark —— 重新打开时不用再挑一次文件夹就能拿回原片访问权。**照片本身从不会被拷进文档里。**
